# Unobserved Change Detection Demo

This document demonstrates the new "Context Gap" detection feature. It shows how the system identifies changes made directly to the repository (outside of an observed Entire agent session) and cross-references them against our Development Memory to explain *why* those files existed in the first place.

## Step 1: Detect a Manual Developer Commit

Imagine a developer manually pushes a commit (e.g., `2d1481b`). This commit was not generated by an agent, so it lacks an Entire checkpoint.

We run our new command against it:

```bash
$ entire-agent-roo detect-context-gap 2d1481b
```

## Step 2: The Context Gap Report

The detector automatically performs the following:
1. Validates that the commit has no Entire footprint.
2. Extracts the `git diff-tree` to find the modified files.
3. Searches the local `.entire/tmp/roo` and Global Storage for any `DevelopmentMemory` where these files were previously modified.
4. Generates a prompt for the next agent/developer to fill in the missing reasoning.

### Example Output

```text
CONTEXT GAP DETECTED

Commit: 2d1481b
Message: feat: add Roo agent adapter with robust JSONL parsing and automated development memory extraction

Changed files:
  - .obsidian/workspace.json
  - JUDGE_WALKTHROUGH.md
  - TRACK3_E2E.md
  - agents/entire-agent-roo/entire-agent-roo.exe
  - agents/entire-agent-roo/test_fixture.go
  - track-3-agent-session.jsonl

Related history:
  - None

Missing context:
  No explicit historical reason was captured.
```

*(Note: If the commit had touched files that were previously part of an agent session, the `Related history` section would list the exact Checkpoint ID and the explicit decisions made during that session, followed by an interactive prompt asking the developer to explain why they deviated from the historical architecture.)*

## How to run this yourself

You can test the logic against any commit in the repository using:
```bash
go run ./agents/entire-agent-roo/cmd/entire-agent-roo detect-context-gap <COMMIT_SHA>
```
